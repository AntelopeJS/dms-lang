## Every page is read-only and writes fail

The module starts with `editable: false`. Set `editable: true` in its `antelope.config.ts` entry and restart the backend. See [Configuration](/docs/modules/lang/configuration).

## The Project files workspace is empty or cannot be edited

Your frontend module is not flagged as the application layer. Add `options: { dmsI18nAppLayer: true }` to its `AddFrontendModule` call. Then check that its locale files are named `<name>-<xx-XX>.json`, such as `app-en-GB.json`, under `i18n/locales`, or under `layers/*/i18n/locales` when the module has a `layers` directory.

## A key shows "From a module" in the project files

An installed module already translates that key, and the text counts as translated. To override it, write a value in the project files. To return to the module's text, drop the override.

## The public URL answers 404

Only the workspaces you create are public. The project files and the installed modules are not served at `/i18n/...`. Check the workspace id and the language code. Workspace ids are case-insensitive.

## The public URL points to the wrong host

Lang builds the URL on the DMS `apiBaseUrl`. Set `apiBaseUrl` to the public origin of your backend.

## Where are the workspaces I created stored?

Each workspace is a `<workspace>/` folder in `workspacesDir`, with one `<locale>.json` per language. Without `workspacesDir`, the folder is the installed module's `i18n-workspaces` folder, and a reinstall of the module wipes it. To keep the workspaces, set [`workspacesDir`](/docs/modules/lang/configuration#module-options) to a folder of your project. Before you move servers, back that folder up, or use **Download backup (.json)** in the workspace's **Danger zone**.

## A new module's translations do not appear

Lang reads the list of frontend modules again whenever the DMS announces a change with its `FrontendModulesChanged` event, so a module registered after Lang started appears without a restart. Check that the module's files are named `<name>-<xx-XX>.json` under `i18n/locales`. Changes to the files of a known module appear on the next read.

## An edit landed in the wrong project file

With several project files per language, Lang writes an existing key back to the file that defines it. It writes a new key to the file that holds the longest part of its namespace, else to `app-<xx-XX>.json`. Put at least one key of a namespace in the file it belongs to, and new keys of that namespace follow it. See [Project files](/docs/modules/lang/configuration#project-files).

## The module fails to load after an upgrade

Upgrade the DMS backend, its interface and the renderer together. The supported `@antelopejs/interface-dms` range is in the README requirements table. The `@antelopejs/dms-frontend` renderer must be in the range that `engines["@antelopejs/dms-frontend"]` of `frontend-vue/package.json` declares. [Troubleshooting](/docs/building/troubleshooting) covers dependency resolution and frontend integration errors.

## The public files answer on the backend but not on the dashboard's origin

The frontend server forwards only the backend prefixes declared to it. Lang declares `/i18n/**` itself through `backendProxies` in `src/frontend-module.ts`. If the files still answer with a page, restart the frontend server so it reads the module's declaration again.
