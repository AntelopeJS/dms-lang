# Extending

The Lang module has no AntelopeJS interface of its own. Other code plugs into it through locale files, the public endpoint, the HTTP API and the realtime topic.

## Ship translations from a module

Any DMS frontend module registered with `AddFrontendModule` contributes its `i18n/locales/*.json` files. Lang discovers them at startup through `GetFrontendModules()` and reads them on every request, so a file change shows on the next read.

```text
frontend-vue/
  i18n/
    locales/
      my_module-en-GB.json
      my_module-fr-FR.json
```

- A module's files appear in the **Installed modules** workspace, read-only. A project redefines a text by overriding the key into its project files.
- Your project's own frontend module carries `options: { dmsI18nAppLayer: true }`: its `app-*.json` files become the writable **Project files**.

::note
Registering a new frontend module requires a backend restart. Changes to existing files do not.
::

## Load a workspace in another app

Every workspace you create is served publicly, without credentials, to any origin:

```bash [Terminal]
curl https://api.example.com/i18n/storefront/fr.json
```

The file is the nested message tree of the language. It leaves out the keys the language has no text for, so load the base language too and let your i18n library fall back. The **Use in your app** card of the [workspace settings](/docs/modules/lang/usage/workspace-settings#use-in-your-app) generates the vue-i18n and i18next setup for you.

## HTTP API

The dashboard pages read and write through `/api/lang/translations`. Every route is reserved to the platform owner (`@AuthOwnerOnly`), and every write also checks the permission of its page action, and requires `editable: true`.

| Method and path | Purpose | Permission (action) |
| --- | --- | --- |
| `GET /workspaces`, `GET /summary` | Every workspace with its locales, keys and coverage | Owner |
| `GET /flat?workspace=` | The flattened keys and values of a workspace | Owner |
| `GET /export`, `GET /backup` | One language as JSON, or the whole workspace as a backup | Owner |
| `POST /workspace`, `POST /import` | Create a workspace, or create one from a backup | Workspaces › create |
| `PATCH /workspace` | Update the description and type | Workspace general › edit |
| `POST /workspace/rename`, `DELETE /workspace` | Rename or delete a workspace | Danger zone › rename, delete |
| `POST /locale`, `DELETE /languages/:workspace/:code`, `POST /languages/:workspace/:code/base` | Add, remove, or make base a language | Workspace general › languages |
| `POST /key`, `POST /key/rename`, `DELETE /key` | Create, rename or delete a key | Matrix › keys |
| `PUT /key`, `DELETE /key/override`, `POST /key/reviewed` | Write values, drop an override, mark a key reviewed | Matrix › edit |

Permission ids follow the page tree, for example `modules.lang.translate.translations.scoped.matrix.edit`, `modules.lang.translate.translations.scoped.matrix.keys` and `modules.lang.manage.workspaces.list.create`.

## Realtime

Every write publishes on the `dms-lang.translations` topic. The Lang pages subscribe to it, so another tab, or another user, sees a change without reloading. Subscribe a page of your own with `RegisterPageTopic` to react to translation changes.

## Deep links

The pages react to query parameters, which you can use in links and quick actions:

| Query | Pages | Effect |
| --- | --- | --- |
| `workspace=<id>` | All | Selects the workspace (`default`, `modules` or one you created) |
| `locale=<code>` | Translation queue | Selects the language |
| `filter=missing` | Translation matrix | Shows the incomplete keys |
| `action=add-key`, `add-language`, `new-workspace` | Matrix, Overview, Workspaces | Opens the matching dialog on arrival |
