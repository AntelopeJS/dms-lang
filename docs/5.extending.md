The Lang module has no AntelopeJS interface of its own. Other code plugs into it through locale files, the public endpoint, the HTTP API, the realtime topic, and the [automation nodes](#automation-nodes) of the DMS procedure builder.

## Supported extension boundary

The contracts on this page are the supported integration points. The runtime root also re-exports its page and route classes. Those exports are not an extension SDK and not a supported subclassing contract. Registering those controllers again, or calling their methods to bypass the HTTP guards, is not supported. Pages of your own are defined through `@antelopejs/interface-dms`, and they integrate with Lang through the locale, HTTP, and realtime contracts below.

## Ship translations from a module

Any DMS frontend module registered with `AddFrontendModule` contributes its `<name>-<xx-XX>.json` files from the [discovered locale directories](/docs/modules/lang/configuration#frontend-module-options). Lang lists the modules with `GetFrontendModules()` and checks the file stamps on each read, so a changed file shows on the next read.

```text
frontend-vue/
  i18n/
    locales/
      my_module-en-GB.json
      my_module-fr-FR.json
```

- A module's files appear in the **Installed modules** workspace, read-only. A project changes one of their texts by overriding the key in its project files.
- The project's own frontend module carries `options: { dmsI18nAppLayer: true }`. Its `<name>-<xx-XX>.json` files become the writable **Project files**, in as many files per language as you like (see [Project files](/docs/modules/lang/configuration#project-files)).

::note
A frontend module that registers or leaves after Lang started, in its own `construct` or `start`, shows up or disappears as soon as the DMS fires `FrontendModulesChanged`, without a restart. Changes to existing files show on the next read.
::

A module registered again with a different `dmsI18nAppLayer` option changes origin on the next module refresh, even when its files have not changed. The messages, the matrix rows, and the coverage then follow the new origin.

## Load a workspace in another app

`GET /i18n/<workspace>/<locale>.json` serves each workspace you create, without credentials, to any origin. The project files and installed modules workspaces are not served there.

```bash [Terminal]
curl https://api.example.com/i18n/storefront/fr.json
```

The response is the nested message tree of the language. It leaves out the keys that have no text in that language. The endpoint does not merge base language texts into the response, so the base language is loaded too and the fallback is configured in the i18n library. The **Use in your app** card of the [workspace settings](/docs/modules/lang/usage/workspace-settings#use-in-your-app) generates vue-i18n, i18next, fetch, and curl snippets for this setup.

After `checkout.pay` is translated to `Payer maintenant` in `fr`, the response includes:

```json [Example response]
{
  "checkout": {
    "pay": "Payer maintenant"
  }
}
```

If `checkout.cancel` exists only in the base language, it is absent from this response.

The response headers are:

- `Access-Control-Allow-Origin: *`, whatever the CORS configuration of the api module. `OPTIONS` preflight requests answer 204.
- `Cache-Control: no-cache`, so a saved change is served on the next request.
- `Content-Language`, the code of the file served.

A regional code without a file of its own falls back to its language. A request for `fr-BE.json` is served the `fr` file, and `Content-Language` is `fr`.

A missing workspace or language answers 404 with the code `unknown_locale`. A valid language with missing keys answers 200. The endpoint has no authentication, so these files hold public texts only.

```json [404 response]
{
  "workspace": "storefront",
  "locale": "de",
  "message": "$dms_lang.errors.unknown_locale",
  "code": "unknown_locale"
}
```

## HTTP API

The dashboard pages read and write through `/api/lang/translations`. Every route is reserved to the platform owner (`@AuthOwnerOnly`). Every write also checks the permission of its page action with `@AuthUserWithPermission` and answers 403 `read_only` unless the module is configured with `editable: true`.

Workspaces are platform-wide catalogs, not tenant-isolated resources. These routes select a workspace by id, not by `tenantId`, and the public `/i18n` route has no tenant or authentication guard. Changing `workspacesDir` changes the process-wide storage root, not its access policy.

A read route that takes `?workspace=` selects the project files (`default`) when the parameter is omitted. An unknown workspace answers 404 `unknown_workspace`.

| Method and path | Purpose |
| --- | --- |
| `GET /workspaces` | Every workspace with its size and public URL, the `editable` flag, and the permission id of each write |
| `GET /summary` | Every workspace with its locales, keys, coverage, and missing counts |
| `GET /workspace?workspace=` | One workspace with its languages and details |
| `GET /flat?workspace=` | The flattened keys and values of a workspace |
| `GET /row?workspace=&key=` | One key of a workspace, with the workspace counts |
| `GET /namespaces?workspace=` | The coverage of each namespace |
| `GET /languages?workspace=` | The languages table of the overview and the workspace settings |
| `GET /kpis?workspace=`, `GET /locale-stats?workspace=&locale=`, `GET /about?workspace=` | The data of the overview figures, the language progress, and the workspace **About** card |
| `GET /notice?workspace=&page=` | The banner of the `overview` or `workspace` page |
| `GET /endpoint?workspace=`, `GET /snippet?workspace=&kind=` | The public URL and the `vue`, `i18next`, `fetch`, or `curl` snippet |
| `GET /languages/:workspace/:code/removal-confirm`, `GET /languages/:workspace/:code/base-confirm` | The texts of the confirmation dialogs |
| `GET /export?workspace=&locale=` | One language as JSON, or every language when `locale` is omitted |
| `GET /backup?workspace=` | The whole workspace as a backup |

| Method and path | Purpose | Permission (component › action) |
| --- | --- | --- |
| `POST /workspace`, `POST /import` | Create a workspace, or create one from a backup | Workspaces › Create workspaces |
| `PATCH /workspace` | Update the description and type | General settings › Edit workspaces |
| `POST /workspace/rename` | Rename a workspace | Danger zone › Rename workspaces |
| `DELETE /workspace` | Delete a workspace | Danger zone › Delete workspaces |
| `POST /locale`, `DELETE /languages/:workspace/:code`, `POST /languages/:workspace/:code/base` | Add, remove, or make base a language | General settings › Manage languages |
| `POST /key`, `POST /key/rename`, `DELETE /key` | Create, rename, or delete a key | Translation matrix › Manage keys |
| `PUT /key`, `DELETE /key/override`, `POST /key/reviewed` | Write values, drop an override, or take translations out of **To review** (created workspaces only) | Translation matrix › Edit translations |

Permission ids follow the page tree. Examples are `modules.lang.translate.translations.scoped.matrix.edit`, `modules.lang.translate.translations.scoped.matrix.keys`, and `modules.lang.manage.workspaces.list.create`. `GET /workspaces` returns the full list under `permissions`.

An error answers a JSON body with `message`, a `$dms_lang.errors.*` i18n key, and `code`, a stable error code that sets the HTTP status.

## Realtime

Every write publishes a `changed` message on the `dms-lang.translations` topic. Its payload carries the `workspace` id, the `keys` the write changed when it changed only keys, and the realtime `session` of the tab that wrote it. The Lang pages subscribe to the topic, so another tab or another user sees a change without reloading. `RegisterPageTopic` subscribes a page of your own to the same topic. A write made by a procedure publishes the same message with the actor `dms:automation` and no session.

## Automation nodes

When the project installs `@antelopejs/interface-dms-automation` (`>=0.7.0 <0.8.0`, an optional dependency) and loads `@antelopejs/dms-automation`, Lang registers 5 triggers, 25 actions and 3 data nodes on start and withdraws them on stop. Without that package, the module runs as before.

A **translation workspace** in these nodes is a Lang catalog: `default` (the project files), `modules` (the installed modules' texts, read-only) or the id of an added workspace. It is not a tenant, and no Lang node takes a `tenantId`: catalogs are platform-wide. The port is named `workspace`, as in the HTTP API.

### Writes

| Node | Does | Translation workspaces |
| --- | --- | --- |
| `lang.set-translation` | Writes or clears one key's text in one language. `checkExpected` with `expectedText` refuses the write when the text changed meanwhile | `default`, added |
| `lang.create-key` | Creates a key with its base text and optional translations, optionally before a sibling | `default`, added |
| `lang.import-language` | Writes up to 5000 texts of one language from a nested or flat object. `merge` writes every given text, `fillMissing` only keys without a text, `replace` also clears the language's other texts (refused on the base language). Unknown keys are skipped and listed, or created with `createKeys`. Every text is checked first: one invalid text fails the step and nothing is written | `default`, added |
| `lang.rename-key`, `lang.delete-key` | Renames or deletes a key in every language. `delete-key` answers `stillVisible` when a module or another project file still shows the key | `default`, added |
| `lang.remove-override` | Removes the project's text of a module key, so the module text shows again | `default` |
| `lang.mark-reviewed` | Takes a key's translations out of **To review** | added |
| `lang.add-language`, `lang.remove-language`, `lang.set-base-language` | Manages the languages of a workspace. A base switch clears review tracking | added |
| `lang.create-workspace`, `lang.import-workspace` | Creates a workspace, or restores one from a backup that `lang.export-workspace` made | added |
| `lang.update-workspace` | Changes the description or the type. A field the procedure leaves untouched keeps its value; a field set to an empty value clears it. A field typed into in the builder and then emptied is sent empty, so it clears the value | added |
| `lang.rename-workspace` | Changes the id; the public URL changes with it, and apps loading the old URL break | added |
| `lang.delete-workspace` | Deletes a workspace and its files. `confirm` must repeat the workspace id. Irreversible | added |

Every write goes through the same code as the dashboard: the same checks, the same files, the same realtime message, and the same triggers. A procedure writes with every right; the per-page permissions apply to dashboard users only. A procedure may write the project files (`default`), on a process where editing is on.

`editable` decides as for the dashboard. On a process where `editable` is off, every write action fails its step with `read_only` before it reads anything, in a test run too, so a test run predicts the real run. The write actions stay registered there, so procedures that use them still load; `lang.workspace-summary` and `lang.list-workspaces` answer `editable` for a procedure to branch on.

A test run of a write runs every check of the real write on the current files and answers what the real run would answer, without writing a file, announcing a change or firing a trigger.

A failed step names the reason in English and ends with the stable error code of the HTTP API, for example `Lang: key "emails.welcome" not found (key_not_found)`.

### Reads and data nodes

| Node | Answers |
| --- | --- |
| `lang.translate` | A key's text in a language, with its parameters filled. The chain is the language, its language subtag (`fr` for `fr-BE`), `fallbackLocale` and its subtag, then the base language; `fallback: false` stops after the subtag. Linked messages (`@:key`) are resolved through the same chain. `onMissing` fails the step (default), answers an empty text, or answers the key |
| `lang.get-key` | Every language's text of a key, its module texts, missing languages, outdated translations and issues |
| `lang.missing-keys`, `lang.keys-to-review` | The keys a language lacks, or the texts to review (`outdated`, `issue` or both), in file order, by pages of at most 500 |
| `lang.language-coverage`, `lang.namespace-coverage` | The Language page's figures for one language, and the overview heatmap |
| `lang.workspace-summary`, `lang.list-workspaces` | A workspace's languages, size and coverage, as `/summary` lists them; every workspace |
| `lang.export-workspace` | The texts as JSON (all, or one language), or a backup. Fails with `export_too_large` above `maxBytes` (1 MB by default, 3 MB at most), so the run log stays small |
| `lang.public-url` | The public URL of a language of an added workspace, and the file the endpoint would serve after its fallback |
| `lang.format-message` (data) | A vue-i18n message with its parameters filled. Linked keys are listed and render empty: a data node reads no file |
| `lang.check-message` (data) | Whether a translation has an issue the way the review queue sees it, reason by reason |
| `lang.language-name` (data) | A language's name from its code, in that language or another |

Reads work whether editing is on or off, and run as they are in a test run.

### Triggers

| Trigger | Fires when | Cluster |
| --- | --- | --- |
| `lang.translations-changed` | A write through Lang succeeded: the dashboard, the HTTP API or a procedure. `operation` names it (`key-created`, `key-updated`, `language-imported`, `workspace-renamed`…). Filters: `workspace`, `operations`, `keyPrefix` | every instance, on the one that wrote |
| `lang.base-text-changed` | The base-language text of a key changed through `PUT /key`, `lang.set-translation` or an override removal. `staleLocales` lists the translations to check | every instance, on the one that wrote |
| `lang.language-completed` | A target language reaches a text for every key, after any write | every instance, on the one that wrote |
| `lang.coverage-below` | A poll finds a language whose coverage went from at least `threshold` (100 by default) to below it. The first poll sets the baseline, unless `fireOnStart` | leader only |
| `lang.module-texts-changed` | The installed modules' texts changed: a module came or left, or a poll of their files found a change. It waits until nothing changed for 5 seconds, then lists the keys added, removed and changed, and the changed ones the project overrides | leader only |

`lang.translations-changed` and `lang.base-text-changed` ignore a write a procedure made, unless their `includeAutomationWrites` setting is on. A circuit breaker stops loops on those two: past 5 procedure-made writes of one key within 60 seconds, the instance drops the trigger's later events and logs a warning. Users' writes are never dropped. `lang.language-completed` has no such setting: it fires once per completion, whoever wrote, since a procedure cannot complete a language again without undoing it first. Every payload of a write carries `origin` (`user` or `automation`), `actorId` for a user, and `originProcedureId` and `originRunId` for a procedure. `deliveryId` is the write's id, followed by `:<locale>` on `lang.language-completed`.

Hand edits of the files and deployments fire no write trigger: there was no write through Lang. The two polling triggers see them.

Payload key lists hold at most 500 keys; `keyCount` gives the total and `keysTruncated` says a list was cut.

### Several instances

`workspacesDir` is on the local disk unless the project mounts shared storage. A write action changes the files of the instance that runs the step, and the write triggers fire on that instance. The polling triggers run on the leader and see its files.

## Deep links

The pages read these query parameters, in links and quick actions:

| Query | Pages | Effect |
| --- | --- | --- |
| `workspace=<id>` | All | Selects the workspace (`default`, `modules`, or one you created) |
| `locale=<code>` | Translation queue | Selects the language |
| `mode=missing`, `issues`, `all` | Translation queue | Selects the queue mode (`missing` by default) |
| `filter=missing`, `complete`, `issues`, `all` | Translation matrix | Filters the rows (`all` by default) |
| `missingIn=<code>` | Translation matrix | Counts and filters on one language |
| `namespace=<name>` | Translation matrix, translation queue | Limits the rows or the queue to one namespace |
| `q=<text>` | Translation matrix | Searches keys and values |
| `key=<path>` | Translation matrix, translation queue | Opens the key drawer on that key, or starts the queue on it |
| `action=add-key` | Translation matrix | Opens the add key dialog on arrival |
| `action=add-language` | Pages with the scope bar | Opens the add language dialog on arrival |
| `action=new-workspace` | Workspaces | Opens the new workspace dialog on arrival |
