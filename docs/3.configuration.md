# Configuration

The module reads its options from its entry in `antelope.config.ts`.

```typescript [antelope.config.ts]
"dms-lang": {
  source: { type: "package", package: "@antelopejs/dms-lang", version: "^0.2.0" },
  config: {
    editable: true,
  },
},
```

## Module options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `editable` | `boolean` | `false` | Allows the running process to create, rename and delete workspaces, add and remove languages, and write keys and translations. When `false`, every write route answers with a read-only error and the pages show the texts without editors. |

::warning
Enable `editable` only where people translate (development, a staging back office). A production process that serves the public locale files usually stays read-only.
::

## Frontend module options

The **Project files** workspace edits the locale files of the frontend modules flagged as the application layer. Set the flag in the `options` of `AddFrontendModule`:

| Option | Type | Description |
| --- | --- | --- |
| `dmsI18nAppLayer` | `boolean` | Marks the frontend module's `i18n/locales/app-*.json` files as the writable project files. Other frontend modules (the DMS, installed modules) stay read-only in the **Installed modules** workspace. |

Locale files follow the DMS adapter convention: one JSON file per namespace and locale, such as `app-en-GB.json` or `lang-fr-FR.json`, under `i18n/locales` (nested `layers/*` folders included).

## Storage and public URL

| What | Where |
| --- | --- |
| Workspaces you create | The module's `i18n-workspaces/<workspace>/` folder, one `<locale>.json` per language |
| Public files | `GET <apiBaseUrl>/i18n/<workspace>/<locale>.json`, open to any origin, `Cache-Control: no-cache` |
| Public origin | The DMS `apiBaseUrl` (the dev server's origin in development) |
| Through the dashboard | The module declares `/i18n/**` to the frontend server as a backend prefix without a session (`backendProxies: [{ path: "/i18n/**", auth: "none" }]`), so the same files also answer on the dashboard's origin |

::note
Only the workspaces you create are served publicly. The project files ship with the dashboard bundle, and the modules workspace is read from the installed packages.
::
