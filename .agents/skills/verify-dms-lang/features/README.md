# Feature map

One file per feature. `covers:` lists the source globs it owns, `docs:` the pages a verdict judges, `journeys/<feature>.mjs` its journeys and `seeded-breaks/<feature>.patch` the break its journeys must catch. `dms-control map` checks that every user-facing file is covered and that every feature has its journeys, its seeded break and existing docs pages.

| Feature | What the user does | Journeys |
|---|---|---|
| [access](access.md) | The Lang pages and the HTTP API under `/api/lang/translations` are reserved to the platform owner. Every write also needs `editable: true` and the permission of its page action. | anonymous-callers-are-refused, read-only-without-editable, read-only-by-default, permissions-follow-the-page-tree |
| [backups](backups.md) | Download backup saves every language of a workspace as one JSON file; Import creates a workspace from such a file. Export hands out one language or all of them. | backup-restores-the-workspace, backup-refusals, export-one-language-or-all, empty-workspace-roundtrip |
| [keys](keys.md) | A key is a dotted path; each language holds a text for it. People add, translate, rename and delete keys, and the module flags a text whose placeholders differ from the base text. | create-translate-read, key-path-rules, message-syntax, update-conflict, rename-and-delete-a-key, mark-reviewed, texts-with-edge-values |
| [languages](languages.md) | A workspace holds one JSON file per language. People add a language by BCP 47 code, remove one, or make another the base that every coverage is measured against. | add-a-language, remove-a-language, make-a-language-the-base |
| [matrix](matrix.md) | Every key of the workspace as a row, every language as a column, with inline editing, status tabs, a key panel, add and delete with undo, and export. | edit-a-cell-saves-and-moves-on, status-tabs-search-and-namespace, key-panel-edits-every-language, add-key-dialog, delete-key-offers-undo, export-menu-counts-the-view, override-a-module-key-from-the-matrix, language-and-namespace-filters, key-panel-renames-and-closing-saves, sidebar-badge-counts-the-project-files, missing-in-and-the-language-columns, groups-collapse-and-stay-as-they-were, cell-line-break-and-failed-save, key-panel-moves-between-keys, key-panel-inserts-a-token-and-saves-on-leave, key-panel-stays-open-on-a-failed-save, back-closes-the-panel, width-is-kept-on-this-device |
| [module-texts](module-texts.md) | The Installed modules workspace (`modules`) lists the texts the DMS and its modules ship, read-only. | [overview](overview.md) | How translated is this workspace: four figures, the languages least complete first, the coverage by namespace and where the keys load from. | use-in-your-app-and-the-heatmap-legend, kpis-and-coverage-by-namespace, header-action-targets-the-least-complete-language, remove-a-language-asks-for-its-code, complete-workspace-has-no-missing-action, quick-actions-in-the-command-palette |
| [package](package.md) | What an app developer installs from the registry: the build, the dashboard layer, the module's own texts and the agent skill. | tarball-holds-what-the-manifest-points-at, published-name-and-interface-ranges |

The verification playground flags its own module, and the journeys rewrite its locale folder in the run's copy. | discovery-by-file-name, layers-replace-the-root-folder, later-file-wins, writes-follow-the-defining-file, delete-uncovers-the-older-definition, rename-stays-in-the-defining-file, dropping-an-override-removes-only-the-winning-one, no-workspace-query-defaults-to-the-project-files, pages-arrive-rendered-by-the-server, reregistering-changes-the-origin, lower-priority-app-layer-merges-first |
| [public-files](public-files.md) | Every workspace a person creates is served as public JSON at `/i18n/<workspace>/<locale>.json`, to any origin and without credentials. | [workspaces](workspaces.md) | A workspace is one set of translation files.
